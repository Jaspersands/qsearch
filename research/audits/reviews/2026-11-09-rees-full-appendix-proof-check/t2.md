## Findings

### 1. GAP: an erroneous chart in thm:bb-envelope can be an invalid instance, and nothing bounds the call made on it

**Location**
- main.tex:1310, thm:bb-envelope(i), "on every branch".
- main.tex:1329: "Remark~\ref{rem:oblivious} bounds each call ... on every oracle".
- appendix:1196-1207: the check after lem:tb-howell-rounds, "possibly of class above $c$ ... whose running time the time-out bounds".
- appendix:1381-1383: lem:tb-count-prime, "on every branch".
- appendix:1445-1448: proof of (iv), "the per-call time-out of Proposition~\ref{prop:tb-recursion}".

**Argument.** On the failure event of lem:tb-kernel, the rows of Y generate only a subgroup of (ker π)^⊥. With approximate transforms they can be anything. Then ker Y need not be an ideal, and lem:tb-chart still outputs constants, namely the coordinates of Y[ε̃_i, ε̃_j]. For e_p = 1 there is no check at all. For e_p > 1 the check after lem:tb-howell-rounds tests only the Lie-ring axioms, and the text explicitly allows "class above $c$".

So a call of Theorem main can receive a non-nilpotent algebra, or one of class above c, which is outside Definition def:input-contract. Two justifications are offered for the call's cost; neither covers this case:
- rem:oblivious quantifies over the function f on a valid instance, not over invalid structure constants.
- The RtF time-out is the device the 9 Nov text calls unneeded (appendix:444-446; main.tex:1296). For e_p = 1 there is no time-out at all.

**Examples.** All are exact-law samples, i.e. the failure event with exact transforms; see `t2/failure_example.out`.
- (p,e,s,c) = (5,2,2,3):
  - ker π is the ideal with rows [[5,0,0,0,0],[0,25,0,0,0],[0,0,5,0,0],[0,0,0,1,15],[0,0,0,0,5]]. This G has order 5^5, class 3 and exponent 25.
  - Y = [[5,14,15,0,5],[5,2,15,0,20]] gives the chart Z/25 ε0 ⊕ Z/5 ε1 with [ε0,ε1] = 15ε0 + 2ε1.
  - The chart passes the stated check, but [[[ε0,ε1],ε0],ε0] = 10ε0 + 3ε1 ≠ 0, and it is not nilpotent.
- e = 1, (5,1,2,3): Y = [[2,2,1,0,0],[0,2,2,0,0]] gives F_5^2 with [ε0,ε1] = 3ε0 + ε1. This non-nilpotent algebra would be the input of the single core call.

**Rates** (`t2/check_chart.out`, Part D):
- Of 316 exact-law failure charts, 201 pass the Lie check, and 49 of those 201 have class > c.
- Running RtF with (N1)-(N6) on such charts hands the solver a socle of class > c in 2411 of 11664 calls (`t2/failure_rtf.out`).

**Effect.** Correctness and the error split are unaffected, since this happens only on the failure event. The query bound probably still holds, because the recursion tree is fixed by (p, m, g_d, ε). But no stated result or argument covers an invalid input.

**Fix.** At appendix:1196, replace "For a prime $p > c$ with $e_p > 1$, before the recursion on the chart of route~(R2) the algorithm checks" with:

> For every prime $p > c$, before any call on its chart, the algorithm checks

Add to the list of conditions:

> and that $\gamma_{c+1}$ of this ring is $0$ ($c$ rounds of brackets with Howell sequences (P1), $O(c\,m^5)$ ring operations)

At appendix:1204-1207, replace "possibly of class above $c$ ... time-out bounds)" with:

> of class at most $c$, so every socle met is a valid instance (Lemma~\ref{lem:tb-section-rank}) and Remark~\ref{rem:oblivious} bounds every call on every branch

At appendix:1445, replace "the per-call time-out of Proposition~\ref{prop:tb-recursion}" with:

> Remark~\ref{rem:oblivious} (every call receives a valid instance, by the chart check)

On the success event the check never fires, so the error split is unchanged. The alternative is to extend rem:oblivious to arbitrary input tensors, with a proof.

### 2. ERROR: the comparison remark draws an unsupported conclusion and misnames HSMC (main.tex:1337)

### 5. MINOR: tab:tb-steps (appendix:1262-1285)
