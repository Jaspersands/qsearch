# Black-box chart acquisition + Rees core: finite end-to-end control (8 Nov 2026)

AI-only, pending human review. A finite check of the draft Corollary cor:black-box
(../2026-11-08-rees-blackbox-corollary-draft.tex); it proves nothing for other groups.

Code: `theorems/rees_blackbox_end_to_end.py`; test: `tests/test_rees_blackbox_end_to_end.py`
(5 passed, 9 Nov). Rerun: `python -m theorems.rees_blackbox_end_to_end GROUP --out GROUP.json`.

The group is seen only through opaque 40-bit handles and a counted multiplication oracle.
The chart comes from the free pullback F_{s,c} -> G (Lazard words), abelian Fourier sampling
for ker phi (law computed exactly from the fibres, float), RREF chart and public checks.
The hiding function is built only after the chart. The core is the scaled exact simulator
(`ext.run_rees_ext`, Rule W per-grade arities, S = m + 4), so query counts are not exactly Q_q.

Every row: kernel equals the true fibre, all chart public checks true, recovered subspace
equals log H, the subgroup generated by the returned handles equals H, the oracle partition
matches the truth, every stage output equals rho_H. No Traceback in any log.

Negative controls (all five groups): (a) naive pullback (products of powers instead of
Lazard words) is rejected by the chart homomorphism check; (b) a single kernel sample is
rejected by the kernel check. Note: the checks catch K' not contained in K, not K' strictly
inside K; the corollary's error term is not removed by them.

(c) Forced K' strictly inside K (9 Nov; `strict_subkernel_control`, recorded under
`negative_controls.strict_subkernel`; test `test_strict_subkernel_is_not_caught_by_public_checks`).
K' = K cap gamma_2(F), built from the true kernel (an approximate Fourier transform could
return it; the exact sampler cannot). Applicable only where it is a proper nonzero
subspace: heis5_s3 (dim K = 3, dim K' = 2). Result: 0 Las Vegas rejections, K' an ideal,
chart Jacobi, class 2, chart exp map a homomorphism on all 390625 pairs, so NOT caught by
any public check. Only the grading-side test sees it: the chart has 625 points but
exp hits the 125 elements of G (not injective). Reason: Phi factors through F/K' as a
Lie homomorphism, so no homomorphism test can see K' strictly inside K. Not applicable
(K = 0, or dim K = 1) for affine5, affine7, free23_5, ut5_5; the affine JSONs predate (c).

ut5_5 (9 Nov). log g0, log g1 span a copy of F_(2,3) in n_5 (grade-4 brackets vanish).
GAP 4.15 independently: order 3125, class 3, exponent 5, IdGroup [3125, 3], 2-generated
(`ut5_5_gap_check.g`, `.out`). Abstractly it is the free23_5 group again: a 2-generator
class-3 Lazard algebra of dimension 5 must be F_(2,3), and every class-3 2-generator subgroup
of UT_5(F_5) is either of this type (order 5^5) or of order 5^4, which is the filiform type
of the UT_4 affine cases. So the new row differs in the black box (5x5 matrix products), the generators and
the pullback, not in the isomorphism type. p = 7 (order 7^5) was not run: the p = 7 core
costs about 4 min per subgroup (affine7) and the exhaustive check would need 2.8e8 pairs.

Homomorphism check (9 Nov). `BlackBox.mul_batch` evaluates a batch of oracle calls with
numpy (each pair still one counted call); the exhaustive limit is now 10^7 pairs, checked in
chunks of 2^20 that stop at the first failing chunk. free23_5 now runs exhaustive (main chart
and naive control). heis5_s3 was rerun for (c); its other numbers are unchanged. The affine5
and affine7 JSONs are from 8 Nov (their checks were already exhaustive). The 9 Nov logs end
with `/usr/bin/time -p` lines: free23_5 366 s wall / 132 s user, ut5_5 245 s / 94 s,
heis5_s3 28 s / 11 s, under nice 19 on a loaded machine.
